## 1. РЕЗЮМЕ ДЛЯ РУКОВОДСТВА

**Synthetic Obsidian** — профессиональный аудио плагин нового поколения для обработки и генерации вокала в DAW (Digital Audio Workstation), предназначенный для музыкантов, продюсеров и звукорежиссёров всех уровней мастерства.

**Основные возможности:**
- Автоматическое определение тональности, темпа, размера и модуляций инструментального трека (GUIDE TRACK)
- AI-powered pitch correction основного вокала без потери естественности и тембра
- Генерация бэк-вокалов (drone, гармонии, дублы) с выбором голоса и стиля
- Редактирование вокала в интерактивном Piano Roll с визуализацией waveform
- Работа как Standalone приложение, VST3 плагин и через ARA2 для глубокой интеграции с DAW

**Целевые платформы:** macOS (Intel и Apple Silicon), Windows 10/11

**График выпуска:**
- **MVP Release:** Standalone + VST3 (без ARA2) — 4-6 месяцев
- **Full Product:** с ARA2 интеграцией и расширенными функциями — 6-9 месяцев

**Ключевые конкурентные преимущества:**
1. Полный workflow вокального продакшена в одном плагине (Melodyne + RVC + DAW плагин)
2. AI-анализ инструментала для точного определения тональности и модуляций в реальном времени
3. Сохранение естественности вокала благодаря гибким параметрам обработки
4. Возможность создания собственных голосовых пресетов через встроенный RVC Creator
5. Эффективная работа с многодорожечными вокальными аранжировками (Drone, Harmony, Double)

## 2. ПРОБЛЕМА И ЦЕЛЕВАЯ АУДИТОРИЯ

### 2.1 Анализ Проблемы

Современные музыканты и продюсеры сталкиваются с серьёзными вызовами при работе с вокалом:

#### Проблема 1: Фрагментированный и неэффективный workflow
Профессиональная обработка вокала требует использования 3-5 различных инструментов:
- **Melodyne или Auto-Tune** для pitch correction и время-зависимых правок
- **RVC (Retrieval-based Voice Conversion)** для генерации бэк-вокалов
- **DAW встроенные инструменты** (Piano Roll, Time-stretch) для ручного редактирования
- **Harmonic synthesizers** для создания многоголосия
- **Анализаторы спектра** для контроля качества

Переключение между этими инструментами отвлекает от творчества, увеличивает время производства на 30-40% и требует глубоких знаний каждого инструмента.

#### Проблема 2: Ручное определение параметров аранжировки
В отсутствие встроенного анализатора, продюсер вынужден:
- Вручную определять ключ инструментального трека на слух (подвержено ошибкам)
- Использовать внешние инструменты (Mixed in Key, Traktor Pro) для BPM анализа
- Вручную отмечать смены тональности (модуляции) на временной шкале
- Проверять время-подпись (3/4, 5/4 и т.д.) вручную

Это замедляет инициирование проекта на 5-15 минут для каждой песни.

#### Проблема 3: Неестественное звучание автотюна
Традиционные инструменты pitch correction создают "робот-эффект":
- Полная синхронизация без вибрато звучит механистично и неживо
- Сохранение оригинального вибрато может привести к расстройке
- Требуется ручная настройка параметров для каждого певца

Следствие: продюсеры избегают pitch correction для вокала, если он записан качественно, либо используют его минимально, что ограничивает творческие возможности.

#### Проблема 4: Сложность генерации многоголосия
Создание бэк-вокалов требует либо:
- Ручного переисполнения (временно-затратно, требует певца)
- Сложной конфигурации RVC моделей (требует технических знаний, время обучения)
- Использования готовых сэмплов (потеря уникальности)

#### Проблема 5: Высокий порог входа для начинающих
Требуемые знания:
- Музыкальная теория (ключи, интервалы, гармонии)
- Специализированное ПО (Melodyne, RVC, DAW)
- Audio engineering (параметры частоты, амплитуды)
- Не существует интуитивного инструмента "всё в одном"

## 3. USER STORIES И СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ

### 3.1 User Story 1: Быстрый pitch correction для демо

**Персона:** Саша, независимый продюсер (24 года, использует Ableton Live)

**Как** продюсер с завершённым инструментальным треком и сырой вокальной записью  
**Я хочу** быстро привести вокал в правильный pitch без заметных артефактов  
**Чтобы** через 30 минут иметь презентабельное демо для отправки лейблу

**Предусловия:**
- У пользователя есть инструментальный трек (full mix или stems)
- У пользователя есть вокальная запись (один или несколько дублей)
- Пользователь использует DAW (Ableton, Logic, Studio One или Reaper)

**Шаги выполнения:**

1. Откроет Synthetic Obsidian как VST3 плагин на вокальной дорожке в DAW
2. Загружает инструментальный трек как **GUIDE TRACK** (drag-and-drop или file browser)
3. Плагин автоматически анализирует трек:
   - Определяет KEY (например, A minor)
   - Определяет TEMPO (например, 120 BPM)
   - Определяет TIME SIGNATURE (4/4)
   - Отправляет результаты в UI: "Key: A min, Tempo: 120 BPM, Time Sig: 4/4"
4. Прослушивает guide track для верификации (Play button)
5. Загружает основной вокал как **MAIN VOX**
6. В UI видит параметры:
   - **Pitch Drift:** 0.5 (слабая коррекция, сохраняет натуральность)
   - **AI Influence:** 0.8 (сильное влияние AI, минимум ручного редактирования)
   - **Formant Shift:** OFF (сохранять оригинальный тембр)
7. Нажимает **ENABLE AI TUNING** — система начинает обработку в реальном времени
8. Прослушивает результат через мониторинг (latency <30ms)
9. Если требуются корректировки:
   - Переходит в **PIANO ROLL** режим
   - Видит визуализацию вокала (waveform) с предложенными нотами (по guide track)
   - Вручную отредактирует отдельные фразы (drag-and-drop ноты)
10. Экспортирует обработанный вокал через **RENDER VOCAL**:
    - Выбирает формат (WAV 24-bit или AIFF)
    - Выбирает параметры: "Render full track" или "Render selection"
    - Плагин экспортирует в течение времени, не превышающего длину трека × 2
11. Загружает экспортированный вокал обратно в DAW на отдельной дорожке
12. Миксует с инструменталом и сохраняет проект

**Критерии приёмки:**
- ✅ Guide track загружается и анализируется за <3 секунды
- ✅ AI tuning обрабатывает 4 минуты вокала за <8 минут (real-time + extra)
- ✅ Вокал звучит натурально без заметного робот-эффекта или цифровых артефактов
- ✅ Вокал остаётся в Key (выстраивается по guide track ±50 cents)
- ✅ Экспорт завершается за время ≤ длина трека × 2
- ✅ Нет пропаданий звука (audio dropouts) при мониторинге
- ✅ После экспорта файл воспроизводится без ошибок в DAW

**Альтернативные потоки:**
- **2A:** Если пользователь не имеет guide track:
  - В UI появляется опция "Manual Key/Tempo Entry"
  - Пользователь вручную вводит KEY (dropdown list всех 12 мажорных и минорных ключей)
  - Пользователь вводит TEMPO (BPM input field)
  - Система работает с этими параметрами

- **2B:** Если анализ guide track завершился с ошибкой:
  - Система показывает сообщение об ошибке: "Could not detect key in this file. Please ensure it's a clear instrumental."
  - Предлагается возможность вручную указать KEY и TEMPO
  - Или загрузить другой guide track

### 3.2 User Story 2: Работа с модуляциями (смены тональности)

**Персона:** Мария, продюсер, работает на 5+ лет (28 лет)

**Как** продюсер, работающий с песней, где меняется тональность (модуляция)  
**Я хочу** чтобы плагин автоматически определил все смены тональности  
**Чтобы** корректно затюнировать вокал в каждой музыкальной секции

**Предусловия:**
- Песня содержит 2+ модуляции (смены ключей)
- Guide track загружена и успешно проанализирована

**Шаги выполнения:**

1. Загружает GUIDE TRACK с модуляциями (например, C minor → E♭ major → F major)
2. Плагин анализирует трек и определяет смены ключей:
   - Временная точка 0:00 - 0:30: **C minor** (основной куплет)
   - Временная точка 0:30 - 1:45: **E♭ major** (припев)
   - Временная точка 1:45 - 2:15: **F major** (бридж/финальный припев)
3. В UI видит **MODULATION TIMELINE**:
   - Горизонтальная временная шкала с отметками каждого ключа
   - Цвет-кодирование: каждый ключ имеет свой цвет (C minor — синий, E♭ — жёлтый, F — красный)
   - Текстовые метки: "C min (0:00)", "E♭ maj (0:30)", "F maj (1:45)"
4. Загружает MAIN VOX
5. Включает **AI TUNING** — система автоматически:
   - Определяет целевой ключ для каждой секции вокала (на основе timeline)
   - Применяет разные параметры коррекции для каждой секции
   - Обрабатывает фразы в C minor с параметрами C, фразы в E♭ — с параметрами E♭ и т.д.
6. Переходит в **PIANO ROLL** режим и видит:
   - Визуализацию вокального waveform'а на полной длине трека
   - Предложенные ноты (по guide track) по цвету соответствующего ключа
   - Вертикальные разделители на временных точках модуляции (визуальные границы)
7. Прослушивает результат фрагмент за фрагментом:
   - 0:00-0:30 (куплет в C min) — проверяет, корректна ли высота в этом ключе
   - 0:30-1:45 (припев в E♭) — проверяет переход и точность в новом ключе
   - 1:45-2:15 (бридж в F) — проверяет финальную секцию
8. Если требуются микроправки:
   - Выбирает отдельную ноту или фразу в Piano Roll
   - Перетягивает ноту вверх/вниз на нужный интервал
   - Система автоматически пересчитывает параметры AI для этой области
9. Может вручную отредактировать timeline модуляций:
   - Кликает на точку модуляции (например, 0:30) и перетягивает её на 0:32 (если она не совпадает)
   - Или добавляет новую модуляцию (кнопка "+ Add Modulation")
   - Или удаляет обнаруженную модуляцию, если она ошибочна
10. Экспортирует готовый вокал как ранее

**Критерии приёмки:**
- ✅ Плагин определяет минимум 2-3 модуляции с точностью до ±100 ms
- ✅ Каждая модуляция корректно определяет целевой ключ (на основе анализа гармонии)
- ✅ AI tuning применяет разные параметры для каждой секции (автоматически переключается)
- ✅ Вокал в каждой секции звучит естественно и в соответствующем ключе
- ✅ Визуализация timeline модуляций понятна и ясна в UI
- ✅ Пользователь может вручную отредактировать точки модуляции без lag'ов
- ✅ Экспорт учитывает все модуляции и сохраняет результат корректно

### 3.3 User Story 3: Создание собственного голосового пресета через RVC

**Персона:** Артём, певец и продюсер (32 года, работает с Logic Pro и Ableton)

**Как** продюсер или певец с уникальным голосом  
**Я хочу** создать собственный RVC пресет на основе своего голоса  
**Чтобы** генерировать гармонии, бэк-вокалы и дублы в собственном голосе

**Предусловия:**
- Пользователь имеет аудио-записи своего голоса (5-30 минут)
- Записи представляют собой чистый вокал (желательно без инструментов и эффектов)
- Пользователь готов потратить 30-60 минут на обучение модели (на CPU) или 5-15 минут (на GPU)

**Шаги выполнения:**

1. В главном интерфейсе плагина нажимает **VOICES** → **CAPTURE MY VOICE** (или в меню BACK VOX → VOICE → NEW)
2. Открывается диалоговое окно **RVC Model Creator**
3. Выбирает источник аудио:
   - Опция A: "Load from files" — загружает аудио-файлы с компьютера (WAV, MP3, AIFF)
   - Опция B: "Record from mic" — записывает живой вокал через микрофон (требует разрешения на доступ к audio input)
   - Опция C: "Import from DAW" — импортирует аудио из открытого DAW (если плагин работает в DAW контексте)
4. Загружает audio dataset:
   - Примеры файлов: "vocal_clean_01.wav", "vocal_clean_02.wav", … (5-30 файлов)
   - Система проверяет качество audio:
     - SNR (Signal-to-Noise Ratio) должен быть >20dB
     - Динамический диапазон достаточный (не слишком сжато)
     - Если качество низкое, система предупреждает: "Audio quality is low. Results may be suboptimal."
5. Выбирает параметры модели:
   - **Gender:** Male / Female (влияет на параметры синтеза)
   - **Genre:** Pop, Rock, R&B, Classical, Gospel, Country (влияет на характер голоса)
   - **Vocal Type (опционально):** Soprano, Alto, Tenor, Bass (помощь в классификации)
   - **Model Name:** "My Voice v1" (для сохранения и идентификации)
6. Опциональные параметры:
   - **Preserve Vibrato:** ON/OFF (сохранять ли вибрато из исходных записей?)
   - **Pitch Range:** Low / Medium / High (помощь в оптимизации для определённого диапазона)
   - **Voice Characteristics:** Breathy, Clear, Dark, Bright (для тонкой настройки звука)
7. Кликает **START TRAINING**
   - Система начинает процесс обучения RVC модели
   - Прогресс-бар показывает процент завершения (0-100%)
   - На GPU (CUDA/Metal): ~5-15 минут для полного обучения
   - На CPU: ~30-60 минут (с предупреждением о времени перед стартом)
8. Во время обучения:
   - Пользователь может закрыть диалог и продолжить работу в плагине
   - Система работает в фоновом потоке
   - При завершении обучения система показывает уведомление: "Model trained successfully!"
9. После завершения:
   - Модель сохраняется в папке плагина (~100-200 MB на диск)
   - Модель автоматически добавляется в список VOICE PRESETS
   - Пользователь видит "My Voice v1" в BACK VOX → VOICE dropdown
10. Теперь пользователь может использовать этот пресет:
    - Загружает BACK VOX трек (или использует BACK VOX generation)
    - Выбирает из dropdown: **VOICE: "My Voice v1"**
    - Выбирает MODE: Drone, Harmony (Third, Fifth, etc.), Double (Octave Up/Down)
    - Система генерирует гармонии в голосе пользователя
11. Может обновить или пересоздать модель:
    - **RETRAIN:** Добавляет новые аудио-файлы и переучивает модель (улучшение качества)
    - **DELETE:** Удаляет модель из системы
    - **EXPORT:** Экспортирует модель для использования на других компьютерах

**Критерии приёмки:**
- ✅ RVC Model Creator загружается и отзывчив (UI не зависает)
- ✅ Аудио-файлы загружаются корректно (WAV, MP3, AIFF поддерживаются)
- ✅ Система проверяет качество audio и показывает warnings при низком качестве
- ✅ Обучение модели завершается за указанное время (5-15 min GPU / 30-60 min CPU)
- ✅ Обученная модель добавляется в VOICE PRESETS и доступна для использования
- ✅ Генерируемые гармонии звучат естественно и в голосе пользователя
- ✅ Модель можно переучить (RETRAIN) для улучшения качества
- ✅ Модель занимает разумный объём памяти (~100-200 MB)

### 3.4 User Story 4: Генерация бэк-вокалов

**Персона:** Катя, инди-артистка (26 лет, создаёт музыку в домашней студии на Ableton)

**Как** певец, создающий инструментальный трек без вокальных слоёв  
**Я хочу** быстро генерировать бэк-вокалы (гармонии, дроны) в правильном ключе  
**Чтобы** создать многослойное звучание без переозвучивания

**Предусловия:**
- GUIDE TRACK загружена и KEY определён
- Пользователь имеет вокальный трек или намерение генерировать "с нуля"

**Шаги выполнения:**

1. В плагине выбирает раздел **BACK VOX** (если нет записанного трека)
   - Опция A: "Generate from scratch" — создаёт новый вокальный трек без исходного аудио
   - Опция B: "Process recorded track" — применяет трансформацию к записанному вокалу
2. Для **Generate from scratch:**
   - Выбирает MODE из dropdown:
     - **Drone:** Однотонный звук на основной тоне (Root, Third, Fifth, Octave)
     - **Harmony:** Автоматическая гармонизация (Third above/below, Fifth, Seventh и т.д.)
     - **Double:** Дубль основного вокала (Octave up/down, Unison с небольшим shift)
     - **Harmony Pack:** Комбинация (Root + Third + Fifth)
   - Выбирает VOICE (встроенный пресет: "Female Soprano", "Male Tenor", "Choir", "My Voice v1" если создана)
   - Выбирает STYLE (Pop, R&B, Gospel, Classical, EDM и т.д.) — влияет на характер гармонии
3. Система генерирует бэк-вокал:
   - На основе KEY из guide track
   - На основе выбранного MODE (генерирует необходимые интервалы)
   - На основе VOICE (применяет RVC трансформацию к выбранному голосу)
   - На основе STYLE (добавляет фразировку, тембр)
4. Результат отправляется в новую audio дорожку (BACK VOX track)
5. Пользователь прослушивает результат:
   - Включает playback в DAW
   - Слышит guide track + основной вокал + новый бэк-вокал одновременно
6. Если результат нравится:
   - Может скопировать эту дорожку на другие части песни
   - Или применить разные MODE/STYLE для разных секций
   - Экспортирует как отдельный файл
7. Если результат требует корректировок:
   - Может отредактировать в Piano Roll (отдельные ноты, интервалы)
   - Может изменить параметры и переге генерировать
   - Может применить эффекты (Pitch Shift, Time Stretch) к результату

**Альтернативный поток (Process recorded track):**

1. Загружает записанный вокальный трек (свой вокал, перепевший в другой octave)
2. Выбирает **VOICE CONVERSION MODE:**
   - **Convert to:** Выбирает целевой голос (от встроенных или custom)
   - **Preserve pitch:** ON/OFF (сохранять ли оригинальный pitch?)
   - **Preserve rhythm:** ON/OFF (сохранять ли оригинальный timing?)
3. Система применяет RVC трансформацию к записанному вокалу
4. Результат — бэк-вокал в голосе целевого пресета, но с оригинальной мелодией
5. Пользователь экспортирует результат

**Критерии приёмки:**
- ✅ Генерация бэк-вокала занимает не более 30 секунд (для 5-минутного трека)
- ✅ Гармонии звучат in-key (на правильных интервалах относительно guide track)
- ✅ Гармонии звучат в унисон (одновременно, без временного смещения)
- ✅ Выбранный VOICE звучит узнаваемо (например, если выбран "My Voice v1", слышна характерность голоса)
- ✅ Бэк-вокал можно редактировать в Piano Roll (изменять отдельные ноты)
- ✅ Результат может быть экспортирован как audio файл или отправлен в DAW как дорожка

## 4. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 4.1 Основные модули системы

#### Модуль 1: GUIDE TRACK Analysis Engine

**Описание:** Автоматический анализ инструментального трека для определения музыкальных параметров.

**Функциональность:**

1. **File Loading**
   - Поддержка форматов: WAV, AIFF, MP3, FLAC (48 kHz, 24-bit и выше)
   - Максимальный размер файла: 2 GB
   - Drag-and-drop интерфейс для загрузки
   - Progress bar с информацией о статусе загрузки

2. **Key Detection**
   - Определение основной тональности (Major/Minor)
   - Поддержка всех 24 ключей (12 мажорных + 12 минорных)
   - Точность: 90%+ на pop, rock, EDM (90% тестовых треков)
   - Результат отображается как: "C minor", "E♭ major" и т.д.
   - Confidence score: система показывает "High", "Medium", "Low" для уверенности в определении

3. **Tempo Detection**
   - Определение BPM (Beats Per Minute)
   - Точность: ±2 BPM от истинного tempo
   - Поддержка диапазона: 40-240 BPM (охватывает большинство жанров)
   - Результат отображается как: "120 BPM"
   - Возможность ручного override (пользователь может установить BPM вручную, если автоматическое определение неверно)

4. **Time Signature Detection**
   - Определение размера (4/4, 3/4, 5/4, 7/8 и т.д.)
   - Точность: 85%+ (сложнее определяется, чем KEY и TEMPO)
   - Результат: "4/4", "3/4" и т.д.
   - Manual override доступен

5. **Modulation Detection**
   - Автоматическое определение смен тональности (модуляций)
   - Точность: каждая модуляция определяется до ±100 ms на временной шкале
   - Результат отображается как временная шкала с отметками каждого ключа
   - Поддержка до 10+ модуляций в одном треке
   - Manual editing: пользователь может добавить, удалить или переместить точку модуляции

6. **Analysis Performance**
   - Анализ 10-минутного трека: <3 секунды (на i5-8400 CPU)
   - Non-blocking: анализ происходит в фоновом потоке, UI остаётся отзывчивым
   - Progress indication: пользователь видит "Analyzing... 45%"

---

#### Модуль 2: MAIN VOX AI Pitch Correction Engine

**Описание:** Автоматическая коррекция вокального питча с сохранением естественности.

**Функциональность:**

1. **Pitch Correction Processing**
   - Автоматическое выравнивание питча вокала к целевым нотам (на основе KEY из guide track)
   - Поддержка полифонии (если в вокале несколько нот одновременно, каждая обрабатывается отдельно)
   - Сохранение вибрато (не удаляется, адаптируется к коррекции)
   - Сохранение динамики (не сжимается, не нормализуется)

2. **Pitch Drift Control**
   - Параметр **PITCH DRIFT** (0.0 - 1.0 scale):
     - 0.0 = Минимальная коррекция (максимальное сохранение оригинального pitch)
     - 0.5 = Средняя коррекция (баланс между натуральностью и точностью)
     - 1.0 = Полная коррекция (максимальное выравнивание к целевым нотам)
   - Default: 0.5 (рекомендуется для большинства вокалов)
   - Влияет на количество "исправлений", которые система применяет

3. **AI Influence Control**
   - Параметр **AI INFLUENCE** (0.0 - 1.0 scale):
     - 0.0 = Нет коррекции (воспроизведение оригинального вокала)
     - 0.5 = Средний уровень AI коррекции
     - 1.0 = Максимальная AI коррекция
   - Default: 0.8 (сильное влияние, минимум ручного редактирования)
   - Позволяет пользователю контролировать степень обработки

4. **Formant Shift Control** (Full Product)
   - Параметр **FORMANT SHIFT** (OFF / -2 to +2 semitones):
     - OFF = Сохранить оригинальный тембр голоса
     - -2 to +2 = Сдвинуть формант (изменить тембр, созданный резонансом гортани)
   - Позволяет "поднять" или "опустить" звучание голоса без изменения pitch
   - Используется для создания harmonic layers с разными тембрами

5. **Vibrato Scaling Control** (Full Product)
   - Параметр **VIBRATO SCALE** (0.0 - 1.0):
     - 0.0 = Удалить вибрато (монотонное звучание)
     - 0.5 = Уменьшить вибрато на половину
     - 1.0 = Сохранить оригинальное вибрато
   - Default: 1.0 (сохранить как есть)
   - Позволяет контролировать выразительность вокала

6. **Real-time Processing**
   - Обработка с latency <30ms (для мониторинга при записи)
   - Non-destructive: оригинальный аудио не изменяется, только playback обработан
   - CPU usage: <25% на i5-8400 при full AI processing

7. **Audio Quality**
   - Не вводит цифровые артефакты (робот-эффект)
   - Результат звучит естественно и живо
   - Сохраняется оригинальный тембр и выразительность голоса

#### Модуль 3: BACK VOX Generation & Processing Engine

**Описание:** Генерация и обработка фоновых вокальных дорожек.

**Функциональность:**

1. **Drone Generation**
   - Создание однотонного фонового вокала (drone)
   - Режимы: Root, Third, Fifth, Octave
   - Поддержка всех 24 ключей
   - Выбор голоса (встроенные + custom RVC presetes)
   - Выбор стиля (Pop, R&B, Gospel, Classical, EDM и т.д.)
   - Результат: чистый, атональный звук, идеален для ambient или подложки

2. **Harmony Generation**
   - Автоматическое создание гармонических слоёв на основе вокала
   - Режимы гармонии: Third Above, Third Below, Fifth, Seventh, Double (Octave Up/Down)
   - Harmony Pack: автоматическая комбинация (Root + Third + Fifth)
   - Каждый слой обрабатывается отдельным голосом (если нужно разнообразие)
   - Результат: многоголосное звучание в выбранном ключе и стиле

3. **Voice Conversion**
   - Применение RVC трансформации к записанному вокалу (голос певца заменяется на выбранный)
   - Сохранение питча и ритма оригинального вокала
   - Сохранение оригинального выражения и нюансов
   - Результат: вокал в голосе целевого пресета

4. **Built-in Voice Presets (MVP)**
   - Минимум 5 встроенных голосов:
     - Female Soprano (яркий, высокий)
     - Female Alto (тёплый, средний диапазон)
     - Male Tenor (светлый, средний-высокий)
     - Male Bass (глубокий, низкий)
     - Choir (многоголосие, обобщённый голос)
   - Каждый пресет имеет характерный тембр и диапазон

5. **Built-in Style Presets (MVP)**
   - Минимум 3 стиля (MVP), расширено в Full Product:
     - Pop (чистый, современный звук)
     - Rock (мощный, резкий)
     - Gospel (выразительный, динамичный)
   - Стиль влияет на характер гармонии, фразировку, добавляет vibrato или dynamics

6. **Custom Voice Presets (RVC Creator)**
   - Создание собственных голосовых пресетов на основе аудио-записей
   - Обучение RVC модели: 30-60 минут на CPU / 5-15 минут на GPU
   - Сохранение и переиспользование модели в future проектах
   - Export/import модели между компьютерами

#### Модуль 4: Interactive Piano Roll Editor

**Описание:** Интерактивное редактирование вокальных нот с визуализацией.

**Функциональность:**

1. **Waveform Visualization**
   - Отображение audio waveform'а вокального трека на временной шкале
   - Масштабирование (zoom in/out) для детального редактирования
   - Цветовое кодирование: зелёный цвет для основного вокала, оранжевый для бэк-вокала

2. **Note Suggestions**
   - Система анализирует waveform и предлагает целевые ноты (на основе guide track key)
   - Предложения отображаются как линии или блоки на временной шкале
   - Каждая нота имеет pitch (высота) и duration (длительность)

3. **Manual Note Editing**
   - Drag-and-drop редактирование:
     - Перетягивание ноты вверх/вниз для изменения питча
     - Перетягивание краёв ноты для изменения длительности (start/end time)
   - Snap-to-grid: привязка нот к музыкальным beat'ам (опционально)
   - Undo/Redo для всех редакций

4. **Pitch Fine-tuning**
   - Редактирование питча с точностью до cents (1 cent = 1/100 semitone)
   - Отображение целевого и текущего питча для каждой ноты
   - Визуальный индикатор "in-tune" vs "out-of-tune"

5. **Timeline & Modulation Markers**
   - Отображение временной шкалы (seconds, beats, bars)
   - Визуальные маркеры для каждой модуляции (смены ключа)
   - Цветовое кодирование: каждый ключ имеет свой цвет в Piano Roll'е

6. **Selection & Batch Editing**
   - Выделение диапазона нот (select all notes in range)
   - Batch operations: сдвинуть all selected notes на определённый интервал (e.g., shift up by a third)
   - Copy/paste отдельных фраз или целых секций

7. **Real-time Playback**
   - Воспроизведение вокала при редактировании (с latency <30ms)
   - Возможность слышать результаты изменений сразу же
   - Mute/solo отдельных трактов (основной вокал, back vocal, guide track)

5. **ARA2 Integration** (Full Product)

## 6. EDGE CASES И ОТКРЫТЫЕ ВОПРОСЫ

### 6.1 Технические Edge Cases

#### Case 1: Неправильный анализ guide track
**Сценарий:** Система неправильно определила KEY (вместо C min определила E♭ maj)

**Текущее поведение:** Вокал затюнируется в неправильный ключ, звучит фальшиво

**Mitigation:**
- Показать Confidence Score для KEY определения (High/Medium/Low)
- Позволить пользователю вручную override KEY
- Предложить alternative keys (top 3 suggestions)
- Документировать, что анализ работает лучше на чистых инструменталах (без вокала)

#### Case 2: Модуляции заканчиваются очень близко друг к другу
**Сценарий:** Быстрые смены ключей (каждые 4 бита) вместо обычных (каждый куплет)

**Текущее поведение:** Система может не определить все модуляции или перепутать noise в signal

**Mitigation:**
- Установить минимальный интервал между модуляциями (e.g., 0.5 seconds)
- Позволить manual editing точек модуляции
- Показать confidence level для каждой детектированной модуляции

#### Case 3: Вокал содержит гармоники (backing vocals уже присутствуют)
**Сценарий:** Guide track содержит вокал (не pure instrumental), система не может корректно определить harmony

**Текущее поведение:** KEY determination может быть неверным

**Mitigation:**
- Документировать, что guide track должна быть чистым инструменталом
- Показать warning если обнаружены вокальные частоты в guide track
- Предложить option удалить вокал из guide track (vocal removal, Phase 3)

#### Case 4: Очень длинные audio файлы (>2 часа)
**Сценарий:** Пользователь пытается загрузить 2+ часовой файл

**Текущее поведение:** Может быть замедление при анализе, проблемы с памятью

**Mitigation:**
- Установить максимальный размер файла (2 GB)
- Показать warning при загрузке больших файлов
- Рекомендовать разбить на smaller segments
- Использовать ленивую загрузку (load on demand)

#### Case 5: Очень быстрые вокальные пассажи (вокальные runs)
**Сценарий:** Вокал содержит быстрые последовательности нот (e.g., 32nd note runs)

**Текущее поведение:** Система может пропустить отдельные ноты в этом пассаже

**Mitigation:**
- Использовать более точный pitch detection алгоритм (e.g., CREPE)
- Позволить пользователю вручную отредактировать быстрые пассажи в Piano Roll
- Показать warning если детектирована очень быстрая последовательность

#### Case 6: Очень низкий или очень высокий питч
**Сценарий:** Басист с very low voice (<80 Hz) или очень высокий soprano (>1000 Hz)

**Текущее поведение:** Система может иметь проблемы с определением pitch на экстремальных значениях

**Mitigation:**
- Проверить диапазон частот при загрузке (предупредить если выходит за пределы)
- Использовать специализированные алгоритмы для экстремальных диапазонов
- Позволить manual specification вокального диапазона (для оптимизации)

#### Case 7: Слишком тихий вокал (низкий SNR)
**Сценарий:** Вокальная запись очень тихая или с высоким уровнем noise

**Текущее поведение:** Система может неправильно определить питч, обработка может привести к усилению noise

**Mitigation:**
- Проверить SNR (Signal-to-Noise Ratio) при загрузке
- Показать warning если SNR <15dB (слишком шумно)
- Рекомендовать пользователю перезаписать или очистить вокал
- Предложить built-in noise reduction (Phase 2+)

#### Case 8: Очень компрессированный вокал (production heavy)
**Сценарий:** Вокал уже значительно обработан (high compression, saturation)

**Текущее поведение:** AI может иметь проблемы отличить natural pitch variations от обработки

**Mitigation:**
- Показать warning если обнаружена high compression (анализируя crest factor)
- Рекомендовать использование slightly higher PITCH DRIFT for natural sound
- Документировать что raw/unprocessed vocals дают лучшие результаты

#### Case 9: Отсутствие GUIDE TRACK
**Сценарий:** Пользователь хочет обработать вокал но нет инструментального трека

**Текущее поведение:** Система не может автоматически определить KEY и TEMPO

**Mitigation:**
- Сделать GUIDE TRACK опциональным (не обязательным)
- Позволить manual entry KEY и TEMPO через UI
- Рекомендовать пользователю загрузить guide track для лучших результатов

#### Case 10: Нет доступного GPU / недостаточный VRAM
**Сценарий:** GPU недоступен, или не хватает памяти для RVC модели

**Текущее поведение:** Система может crash или использовать очень медленный CPU fallback

**Mitigation:**
- Gracefully fallback на CPU если GPU недоступен
- Показать warning о медленной скорости при CPU-only processing
- Оптимизировать модели для работы с низким VRAM (quantization, pruning)
- Документировать минимальные требования

### 6.2 UX Edge Cases

#### Case 1: Первый запуск новым пользователем
**Сценарий:** Пользователь не знает как загрузить guide track, какие параметры использовать

**Mitigation:**
- Встроенный onboarding tutorial (первый запуск)
- Пример проекта с готовыми параметрами
- Интерактивные подсказки ("Hint: Drag guide track here")
- Quick start guide (2-3 минуты)

#### Case 2: Пользователь потеряет несохранённый проект
**Сценарий:** Плагин crash'ится или пользователь закрыл проект без сохранения

**Mitigation:**
- Auto-save каждые N минут (e.g., 5 minutes)
- Recovery механизм при следующем запуске ("Found unsaved project, recover?")
- Backup копии проектов в temp папке

#### Case 3: Пользователь не понимает Parameter UI
**Сценарий:** Пользователь не знает что означает "Pitch Drift" или как его использовать

**Mitigation:**
- Hover tooltips для каждого параметра
- "?" button для расширенной справки
- Preset'ы с осмысленными названиями (e.g., "Natural", "Aggressive", "Subtle")
- Видео-туториалы для основных параметров

#### Case 4: Результат обработки звучит плохо (robot effect)
**Сценарий:** Пользователь применил full AI tuning и результат звучит неестественно

**Mitigation:**
- Рекомендовать уменьшить AI INFLUENCE (попробовать 0.6 вместо 1.0)
- Предложить preset "Natural" который использует консервативные параметры
- Документировать что different vocalists требуют different settings
- Позволить undo и перепробовать с другими параметрами

### 9.2 Architecture & Threading Model

#### High-Level Architecture:

```
┌─────────────────────────────────────────┐
│ User Interface (JUCE UI Thread)         │
│ - Piano Roll, Controls, Visualization   │
└────────────┬──────────────────────────┘
             │
      ┌──────┴───────┬──────────────┬─────────────┐
      │              │              │             │
┌─────▼────┐  ┌─────▼────┐  ┌─────▼────┐  ┌────▼──────┐
│ Audio    │  │ Analysis │  │ RVC      │  │ Render    │
│ Thread   │  │ Thread   │  │ Thread   │  │ Thread    │
│ (Real)   │  │ (Async)  │  │ (Async)  │  │ (Async)   │
└──────────┘  └──────────┘  └──────────┘  └───────────┘
      │              │              │             │
      └──────────────┴──────────────┴─────────────┘
             │
      ┌──────▼───────────────┐
      │ Shared Data Store    │
      │ (Lock-free buffers)  │
      └──────────────────────┘
```

#### Threading Strategy:

1. **UI Thread (JUCE Message Thread):**
   - Handles all UI updates, user interactions
   - Non-blocking (long operations run on separate threads)
   - Safe for: GUI updates, parameter changes, file dialogs

2. **Audio Thread (Real-time):**
   - Processes audio in real-time (VST3 processBlock callback)
   - Strict latency budget: <30ms
   - No allocations, no locks, deterministic performance
   - Handles: Pitch correction DSP, basic effects, audio output

3. **Analysis Thread (Worker):**
   - Guide track analysis (Key, Tempo, Modulation detection)
   - Non-blocking (UI remains responsive)
   - Priority: Normal or Low (not real-time critical)
   - Completed analysis posted back to UI thread via message

4. **RVC Processing Thread (Worker):**
   - RVC model inference and voice conversion
   - Can be GPU-accelerated (CUDA on Windows, Metal on macOS)
   - Lower priority than audio thread
   - Completed results posted to audio thread via lock-free buffer

#### Synchronization Mechanism:

- **Lock-free Ring Buffer** for audio data exchange between threads
- **Message Queue** for UI-to-Worker communication
- **Atomic flags** for state synchronization (is_processing, should_stop)
- **Mutex** only for non-real-time operations (file I/O, model loading)

### 9.3 Identified Risks & Mitigation Strategies

| # | Risk | Probability | Impact | Mitigation |
|---|------|-------------|--------|-----------|
| 1 | RVC model quality poor on diverse voices | Medium | High | Early prototyping, user feedback loop, fallback to simpler voice conversion methods |
| 2 | Modulation detection inaccurate on edge cases | Medium | Medium | Implement multiple detection algorithms, manual override UI, confidence scores |
| 3 | DAW compatibility issues (VST3 host bugs) | Low | High | Extensive testing on all target DAWs, monitor VST SDK updates, maintain compatibility layer |
| 4 | GPU memory exhaustion with large models | Low | Medium | Graceful fallback to CPU, model quantization, warning UI before processing |
| 5 | Audio latency spikes (audio glitches) | Low | High | Real-time priority for audio thread, buffer optimization, preallocation, profiling |
| 6 | RVC model licensing/copyright issues | Low | High | Legal review of models, proper attribution, consider proprietary models later |
| 7 | Pitch detection algorithm fails on uncommon genres | Medium | Medium | Support multiple algorithms, manual fallback, user education |
| 8 | Performance regression after optimizations | Low | Medium | Performance benchmarks in CI/CD, regression tests |
| 9 | User data loss (crash without save) | Low | High | Auto-save every N minutes, recovery mechanism, backup copies |
| 10 | Dependency vulnerabilities (security issues) | Low | Medium | Regular dependency updates, security scanning (e.g., Dependabot) |
