### ✅ Вопрос 1: Лицензия RVC (AGPL-3.0 vs коммерческая альтернатива)

**Контекст:** RVC v2/v3 распространяется под лицензией AGPL-3.0, которая обязывает раскрывать исходный код любого модифицированного ПО, использующего RVC. Это может быть несовместимо с коммерческой моделью продукта (закрытый исходный код).

**Варианты ответа:**
- **Вариант A:** Принимаем AGPL-3.0 и раскрываем исходный код плагина как open-source
  - *Последствия:* Упрощенная разработка, сильное сообщество, но потеря конкурентного преимущества от исходного кода. Требуется обновление бизнес-модели (пожертвования, premium сервисы, услуги).
- **Вариант B:** Ищем коммерческую альтернативу (proprietary voice conversion model)
  - *Последствия:* Сохранение закрытого кода и коммерческого контроля, но: затраты на лицензирование, более длительная разработка, поиск/интеграция альтернативы (возможный прогиб сроков на 2-4 недели).
- **Вариант C:** Используем RVC через сервис API (облачное преобразование)
  - *Последствия:* Чистая архитектура, но зависимость от облачной инфраструктуры, затраты на хостинг, privacy concerns (данные пользователя на серверах).

**Влияние на:** лицензирование, бизнес-модель, архитектура, бюджет, сроки

**Кто задаёт:** Продакт Менеджер, Legal

### ✅ Вопрос 2: ARA2 в MVP или Phase 2?

**Контекст:** ARA2 (Audio Random Access 2) — расширенный протокол интеграции между плагином и DAW, позволяющий глубокий доступ к дорожке/сессии. Это снимает много ограничений VST3, но требует дополнительных 3-4 недель разработки и поддерживается только в новых версиях DAW (Logic Pro 11+, Cubase 13+, Studio One 6.5+).

**Варианты ответа:**
- **Вариант A:** ARA2 с первой фазы (MVP включает и VST3, и ARA2)
  - *Последствия:* Расширенный функционал сразу (доступ к гармонии, темпу сессии, автоматизация параметров), но: дополнительные сроки, сложность тестирования, ограниченная совместимость с DAW.
- **Вариант B:** MVP только VST3, ARA2 во вторую фазу (через 2-3 месяца после релиза)
  - *Последствия:* Быстрый выпуск, широкая совместимость со всеми DAW, но: урезанная функциональность в дебюте, необходимость рефакторинга архитектуры для ARA2 позже.

**Влияние на:** архитектуру (интеграция слоя ARA2 с самого начала), сроки (3-4 недели разницы), функциональность MVP

**Кто задаёт:** Продакт Менеджер, Dev1

### ✅ Вопрос 3: RVC Training — локально на машине пользователя или облако?

**Контекст:** Пользователи могут захотеть обучить модель RVC на своем собственном голосе для максимальной персализации. Тренировка требует вычислительных ресурсов (GPU), хранения обучающих данных и времени (30 мин – 2 часа в зависимости от размера датасета).

**Варианты ответа:**
- **Вариант A:** Локальная тренировка встроена в плагин/standalone
  - *Последствия:* Полный контроль пользователя, privacy (данные не покидают машину), но: высокие требования к оборудованию, медленно на слабых GPU, усложняет UI/UX.
- **Вариант B:** Облачная тренировка через сервис (пользователь загружает данные, получает готовую модель)
  - *Последствия:* Просто для пользователя, масштабируемо, но: privacy concerns, затраты на облачные вычисления, требуется сеть, зависимость от сервиса.
- **Вариант C:** Вообще без тренировки (pre-trained models только)
  - *Последствия:* Минимальные требования, простота, но: меньше персализации, пользователи ограничены предложенными голосами.

**Влияние на:** архитектуру (встройка ML фреймворка vs API интеграция), бюджет (облачная инфраструктура?), UX (сложность?), требования к ПК

**Кто задаёт:** Продакт Менеджер, Dev2

### Вопрос 4: Обязателен ли Guide трек (опорный вокал)?

**Контекст:** RVC требует входного аудио (вокал на любом языке/голосе) для преобразования. Это может быть: (a) вокал пользователя, (b) pre-recorded гайд-трек, (c) синтезированный/AI-generated вокал. Вопрос в том, обязателен ли гайд-трек для базовых сценариев или пользователь может использовать плагин только на существующем вокале.

**Варианты ответа:**
- **Вариант A:** Плагин работает ТОЛЬКО на входном аудио (пользователь выбирает трек с вокалом)
  - *Последствия:* Простая архитектура, низкие требования к UX, но: пользователь должен иметь или записать вокал, меньше творческой свободы.
- **Вариант B:** Поддерживаем MIDI input + синтезированный гайд (пользователь играет мелодию на клавиатуре)
  - *Последствия:* Больше гибкости (можно генерировать вокал на лету), но: нужна интеграция с text-to-speech/MIDI-to-voice синтезатором, сложнее архитектура, больше требований к GPU.

**Влияние на:** UX (friction пользователя), архитектуру (встройка синтезатора?), требования к входным данным

**Кто задаёт:** Продакт Менеджер, UX Designer

### Вопрос 5: Распространение моделей — bundled или lazy-load?

**Контекст:** Pre-trained RVC модели (для разных голосов) занимают ~150-200 MB каждая. Вопрос: включаем ли мы модели в инсталлятор (большой размер, быстро), или пользователь скачивает их при первом запуске (меньше инсталлятор, медленнее первый старт)?

**Варианты ответа:**
- **Вариант A:** Bundled модели (инсталлятор ~800 MB – 1.5 GB)
  - *Последствия:* Готово к работе сразу, но: большой размер инсталлера, медленная загрузка, требует диска, версионирование сложнее.
- **Вариант B:** Lazy-load (инсталлятор ~50-100 MB, модели скачиваются по требованию)
  - *Последствия:* Легкая инсталляция, динамические обновления моделей, но: первый запуск медленный, требует интернета, сложнее UX (индикаторы загрузки).
- **Вариант C:** Гибридный подход (базовый набор bundled, дополнительные модели опционально)
  - *Последствия:* Баланс, но: усложняет управление версиями и инсталляцию.

**Влияние на:** размер дистрибутива, UX (friction первого запуска), требования к интернету, обновления

**Кто задаёт:** Продакт Менеджер, Dev1

### Вопрос 6: Pricing model (one-time / subscription / freemium)?

**Контекст:** Модель монетизации повлияет на дизайн функций (feature gating), лицензирование и стратегию маркетинга. Вариант: одноразовая покупка $49-199, подписка $5-15/месяц, freemium (базовое бесплатно, advanced платно)?

**Варианты ответа:**
- **Вариант A:** One-time purchase ($99-199, постоянная лицензия)
  - *Последствия:* Понятно пользователям, стабильный доход авансом, но: сложнее мотивировать обновления, меньше recurring revenue.
- **Вариант B:** Subscription ($9.99/месяц или $99/год)
  - *Последствия:* Predictable MRR, мотивация к постоянным обновлениям, но: меньше привлекательно для одноразовых покупателей, требует инфраструктуру подписки.
- **Вариант C:** Freemium (бесплатно с ограничениями, $49/месяц для Pro)
  - *Последствия:* Низкий barrier to entry, вирусный потенциал, но: требует отлаженной feature gating, сложнее монетизация.

**Влияние на:** design (какие фичи платные?), маркетинг, архитектуру (licensing система), revenue

**Кто задаёт:** Продакт Менеджер, Бизнес

### Вопрос 7: Целевые DAW для MVP-тестирования

**Контекст:** Невозможно протестировать плагин во всех DAW сразу. Нужно выбрать 2-3 приоритетных DAW для MVP (например, Ableton Live, Logic Pro, Reaper) и гарантировать стабильность там, остальное позже.

**Варианты ответа:**
- **Вариант A:** Ableton Live + Logic Pro (основные целевые пользователи)
  - *Последствия:* Сфокусированная разработка, высокое качество в этих DAW, но: может быть несовместимость в других (Studio One, Cubase).
- **Вариант B:** Reaper + Cubase + Studio One (профессиональные DAW)
  - *Последствия:* Охват профессиональной сферы, но: разнородная совместимость, сложнее тестировать.
- **Вариант C:** Все популярные DAW одновременно (Ableton, Logic, Reaper, Cubase, Studio One)
  - *Последствия:* Полное покрытие, но: очень долго, требует большого QA ресурса.

**Влияние на:** сроки разработки, QA стратегия, целевая аудитория, PR стратегия

**Кто задаёт:** Продакт Менеджер, Dev1

### Вопрос 8: macOS AU формат нужен кроме VST3?

**Контекст:** На macOS существует старый стандарт Audio Units (AU), который все ещё поддерживается некоторыми DAW (Logic Pro, GarageBand, старые версии Ableton). VST3 на macOS поддерживается новыми версиями DAW. Вопрос: инвестируем ли в AU поддержку для обратной совместимости или только VST3?

**Варианты ответа:**
- **Вариант A:** Только VST3 (macOS и Windows)
  - *Последствия:* Упрощение, меньше кода, но: потеря пользователей старых Logic Pro (< 11.0), GarageBand.
- **Вариант B:** VST3 + AU (macOS специально)
  - *Последствия:* Охват старых пользователей, better market penetration, но: +2-3 недели разработки, двойная поддержка.

**Влияние на:** сроки (2-3 недели), поддержка (двойная работа?), совместимость, market reach на macOS

**Кто задаёт:** Продакт Менеджер, Dev1

### ✅ Вопрос 9: Минимальные системные требования (RAM, GPU?)

**Контекст:** RVC inference требует вычислительных ресурсов. Вопрос: какой минимум ЦП/ОЗУ/ГПУ мы гарантируем? Это влияет на целевую аудиторию и оптимизацию.

**Варианты ответа:**
- **Вариант A:** Низкие требования (Intel i5/8GB RAM, GPU опциональный, работает везде)
  - *Последствия:* Большая аудитория, но: медленная обработка на слабых машинах, требует оптимизации кода, CPU fallback.
- **Вариант B:** Средние требования (Intel i7/16GB RAM, NVIDIA/AMD GPU рекомендуется)
  - *Последствия:* Быстрая обработка в реальном времени, целевая аудитория — семи-профессионалы, но: исключаем бюджетных пользователей.
- **Вариант C:** Высокие требования (Intel i9/32GB RAM, NVIDIA RTX GPU обязателен)
  - *Последствия:* Максимальная производительность, но: узкая аудитория (только профессионалы с дорогим оборудованием).

**Влияние на:** целевую аудиторию, оптимизацию (GPU/CPU), маркетинг (positioning), затраты на разработку (поддержка старого оборудования трудозатратна)

**Кто задаёт:** Продакт Менеджер, Dev1

### Вопрос 10: Планируется ли Cloud Sync голосовых пресетов?

**Контекст:** Пользователи могут создавать/сохранять собственные voice presets (настройки для разных голосов). Вопрос: синхронизируем ли мы эти пресеты в облако (чтобы пользователь мог использовать их на разных машинах/DAW) или пресеты локальные?

**Варианты ответа:**
- **Вариант A:** Облачная синхронизация (учётная запись пользователя, облако, синхронизация между устройствами)
  - *Последствия:* Удобство для профессионалов, лучше UX, но: требуется облачная инфраструктура (БД, API, хостинг), privacy concerns, затраты на сервер (~$500-1500/месяц).
- **Вариант B:** Локальные пресеты (файлы на диске пользователя, export/import вручную)
  - *Последствия:* No cloud costs, простая реализация, но: user friction (ручной экспорт), хуже UX для работы на разных машинах.
- **Вариант C:** Встроенная синхронизация через облако пользователя (iCloud/Google Drive)
  - *Последствия:* Используем облако пользователя (экономия), но: сложнее реализация, зависимость от третьих сервисов.

**Влияние на:** архитектуру (backend нужен?), инфраструктуру, затраты на хостинг, UX, privacy

**Кто задаёт:** Продакт Менеджер, Dev2
