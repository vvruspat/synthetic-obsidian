## Расширенный датасет для дообучения

`build_augmented_dataset.py` собирает отдельный, возобновляемый набор:
копии ручных оригиналов, четыре варианта Seed-VC на каждый train-клип
(низкий/средний/высокий регистр и исходный регистр с заменой тембра)
и два варианта phase-vocoder pitch shift. Для текущих 53 обучающих
оригиналов запланированы 318 производных записей. Используются шесть
акустических референсов, выбранных по CAMPPlus только среди train;
число референсов не равно подтверждённому числу певцов.

Сборка `~/Music/Models/Sasha-dataset/augmented-2026-10-22-v1/` завершена:
**371 train-клип, 3.05 часа**, включая 53 ручных оригинала и 318 производных
(212 Seed-VC и 106 DSP). Вместе с validation 14 и test 8 — 393 клипа.
Из автоматической разметки масками исключены 74.53 с; доступно 3.03 часа
обучающего времени. Все 393 WAV/JSON прошли проверку хешей, длительностей,
чисел, путей и происхождения границ. Точных дубликатов декодированного звука
нет. 32 теста прошли. На отдельном контроле 102.44 с с известным сдвигом
MAE переноса 30.64 → 6.46 мс, p95 16.29 мс; это не ручная оценка всей
нейросинтетики. Рабочая v7 и исходная ручная разметка сохранены.

Исходные записи и `vox_243` замораживаются побайтовыми копиями с SHA-256,
прежние роли сохраняются. `vox_243` — validation. Для синтеза и голосовых
референсов validation/test недоступны. Исходная `notes/` не меняется.

Выравнивание по Whisper/RMVPE поддерживает длинные записи через окна
с перекрывающимся контекстом на общей 20-мс сетке. Ноты не добавляются
и не удаляются. Ненадёжные сопоставления, потеря озвученности и ошибки
контура высоты создают `ignore_intervals` с запасом 80 мс. На этих кадрах
`train.py` отключает **все три цели**, а баланс классов считает только
конечные значения. Слишком ненадёжный вариант исключается из манифеста.
Автоматические метки сохраняют своё происхождение и не объявляются
ручной проверкой. Ни веса, ни предсказания модели границ для меток не используются.

`augmentation.read_prepared` проверяет относительные пути, SHA-256,
замороженные роли, происхождение референсов, монотонность карты времени,
перенос каждого ручного края и маски. `train.py --synthetic-weight 0.25`
позволяет уменьшить частоту выборки синтетических окон при множестве копий;
по умолчанию 1 сохраняет прежнее обычное перемешивание.

Сборка использует существующий локальный Seed-VC, загружает модели один раз
и фиксирует hashes весов, seeds и снимки кода. По повторному запуску
готовые результаты проверяются и пропускаются. Пример для текущей базы:

```sh
research/.venv_seed_vc/bin/python -m research.native_notes.build_augmented_dataset \
  --base data/native_note_boundary_v7/selected/manifest.json \
  --validation-manifest data/native_note_boundary_v8_pitchaug/dataset/prepared.json \
  --voicing data/native_note_boundary_v7/voicing \
  --output "$HOME/Music/Models/Sasha-dataset/augmented-2026-10-22-v1"
research/.venv_seed_vc/bin/python -m research.native_notes.summarize_dataset \
  --dataset "$HOME/Music/Models/Sasha-dataset/augmented-2026-10-22-v1"
```

`--limit 6` выполняет возобновляемый первый пакет. Сводка пишет `README.md`,
`dataset-summary.json`, переносимый `metadata.jsonl` и список отбраковки.
Для промежуточного отчёта есть `summarize_dataset --allow-partial`.
Каждая пара `clip.wav` / `clip.annotation.json` открывается в JUCE.
Количество производных и пригодных часов следует брать из итоговой сводки,
а не из плана. Синтез увеличивает число представлений, а не число независимых
ручных исполнений. Сам сборщик не запускает дообучение и не переключает v7.

32 теста покрывают перенос границ, длинные записи, маски, отсутствие градиента
на неуверенных кадрах, замороженные роли, проверку карт времени и баланс
выборки оригиналов/синтетики. C++/JUCE и audio thread не менялись;
новых зависимостей нет. Windows для этой сборки не проверялся.

Для последней строки нужны начало в пределах 50 мс и конец в пределах
max(50 мс, 20% длительности эталонной ноты). Используется взаимно однозначное
максимальное сопоставление. **Высота в эту метрику не входит.**
У AI 134 правильных начала, 54 лишних, 23 пропущенных; правильны обе границы
92 из 157 эталонных нот. Это экспериментальный помощник, требующий проверки.
Две песни не устанавливают качество на всех исполнителях и условиях записи.
Разделение по исполнителям не проверялось: singer IDs в экспортах не заполнены.

Нативный C++ и PyTorch дали одинаковые интервалы на контрольных WAV 44,1/48 кГц.
Максимальное отличие признаков — 0,000035, вероятностей — 0,0000024.
Проверка выполняется `evaluate_native.py`, отдельно от обучения и выбора порогов.

В этой исторической версии авточерновики дополнительно исключали интервалы
без уверенного YIN-кадра (участки `C4 ?`). 23 октября 2026 этот постфильтр
убран по запросу пользователя. Текущий `evaluate_native.py` сравнивает все
вероятности с PyTorch и проверяет сырые декодированные интервалы без удаления
по неуверенной высоте. Веса и схема модели этим изменением не меняются.

Артефакты установлены локально:

- `~/.synthetic_obsidian/models/note-boundaries/sasha-v1/model.json` — переносимые веса для JUCE, около 1,5 MiB.
- Там же `report.json` — история обучения и замороженные метрики.
- `~/.synthetic_obsidian/training/note-boundaries/sasha-v1-2026-10-17/` — checkpoint, манифест, отчёты.

Модель загружается в рабочем потоке по необходимости. Нативный запуск не
использует Python, ONNX Runtime, сеть или GPU. JSON имеет строгий фиксированный
контракт, предельный размер 4 MiB и проверку размеров/конечных чисел.
Любая ошибка загрузки возвращает прежний математический анализ.
Формат параметров/состояния плагина и его audio callback не изменяются.

## Цикл дальнейшей разметки

1. Открыть обновлённый **Vocal Note Annotator**, выбрать **AI note boundaries**.
2. Открыть новый вокал: модель создаст черновик автоматически. Для уже открытой
   записи нажать **Generate draft**; предложение сохранится в отдельном sidecar,
   оригинальная разметка останется целой. Undo возвращает предыдущие ноты.
3. Исправить лишние/пропущенные ноты и края. Началом считать начало атаки;
   вибрато не разрезать на отдельные ноты, повторную атаку на той же высоте
   можно разметить отдельно. Высоту пока предлагает YIN, её можно поправить.
4. После проверки **всего клипа** отметить **Entire clip checked by hand**.
   Заполнить одинаковый `Song / recording session ID` для фрагментов одной песни.
   Это позволит удержать их в одной части обучающей выборки.
5. **Export dataset** в папку датасета. Для нового обучения сохраняется исходный
   audio ID, а повторные экспорты одного ID дедуплицируются по последней версии.
   Исправления сохраняют ID/SHA256 модели, которая предложила черновик.

## Повторить первую подготовку

Из корня репозитория, в уже существующем изолированном окружении:

```sh
research/.venv_seed_vc/bin/python -m research.native_notes.train \
  --dataset "$HOME/Music/Models/Sasha-dataset/notes" \
  --output data/native_note_boundary_v1 \
  --pretrained data/gtsinger_alignment/multilingual_mps_full_breath_diffcut_encoder_thr075_tcn.pt \
  --accept-user-reviewed --distinct-songs --epochs 100
```

`--accept-user-reviewed` — явное разрешение считать переданные разметки
проверенными, несмотря на старый флаг. Для новых итераций вместо этого
используйте отметку проверки в редакторе и прежний доверенный манифест.
Рекомендуется не перезаписывать каталоги прежних экспериментов.

## Следующая итерация

Следующая команда использует исправленные экспорты, сохраняет неизменные
train/validation/test роли старых записей и принимает старые `draft`-файлы
**только если их точный SHA256 уже был подтверждён в исходном манифесте**:

```sh
research/.venv_seed_vc/bin/python -m research.native_notes.train \
  --dataset "$HOME/Music/Models/Sasha-dataset/notes" \
  --output data/native_note_boundary_v2 \
  --resume "$HOME/.synthetic_obsidian/training/note-boundaries/sasha-v1-2026-10-17/checkpoint.pt" \
  --trusted-manifest "$HOME/.synthetic_obsidian/training/note-boundaries/sasha-v1-2026-10-17/manifest.json" \
  --name "Sasha notes v2" --model-id sasha-notes-v2 --epochs 100
```

Это новая адаптация весов, а не восстановление состояния optimizer. Чтобы
сравнивать версии честно, не используйте отложенные песни для подбора изменений
модели; собирайте новые отложенные песни по мере роста датасета. Если новые
session IDs объединяют прежние train/test записи, программа отклонит такое
противоречивое разделение вместо тихой утечки.

При дообучении выбор эпохи и порогов производится совместно на validation.
Если ни одна эпоха не лучше исходных весов, сохраняется кандидат эпохи 0;
сам факт добавления данных не является основанием заменить хорошую модель.

Для native YIN-признаков добавьте `--native-runner` с путём к
`NativeNoteAnnotatorTests`. Тренер извлекает диагностики для каждого WAV
в `voicing/`. Калибровка и выбор эпохи используют все декодированные
интервалы, включая участки без уверенной высоты. Исправленные границы из
пользовательского JSON остаются целями обучения.

`--learning-rate-scale 0.25` уменьшает оба шага обучения вчетверо, сохраняя
их соотношение. Для сравнения нескольких настроек используйте `--skip-test`:
в `report.json` тестовые метрики будут `null`. После выбора по validation
проверьте один итоговый вариант через `evaluate_native.py`, а старую и новую
модели сравнивайте на одинаковых отложенных записях с одинаковой политикой декодирования.

В редакторе выбрать **Model... → новый `model.json`**. Пересобирать приложение
для следующей версии не требуется. Автоматическое дообучение после экспорта
не запускается: новая разметка должна сначала пройти ручную проверку.

## Проверки

```sh
research/.venv_seed_vc/bin/python -m unittest research.native_notes.test_pipeline -v
ctest --test-dir build-native-note/tools/native_note_annotator --output-on-failure
research/.venv_seed_vc/bin/python -m research.native_notes.evaluate_native \
  --runner build-native-note/tools/native_note_annotator/NativeNoteAnnotatorTests_artefacts/Release/NativeNoteAnnotatorTests \
  --experiment data/native_note_boundary_v1 \
  --output data/native_note_boundary_v1/native-validation
```

Тренировка использует уже установленные PyTorch, librosa, NumPy и SoundFile;
новые зависимости не добавлены. Feature contract: более сильный канал,
линейный ресемплинг до 16 кГц, центрированный periodic Hann FFT 512, hop 160,
Slaney mel 64 (40–7600 Гц), динамический диапазон 80 дБ, нормализация каждой
полосы по целому клипу. Матрица mel-фильтров хранится с весами. Переносимая
C++-реализация проверяется против этого точного контракта, включая padding.
